# SFTP 设计

SFTPCore 通过系统 OpenSSH 的 sftp 子系统收发 SFTP v3，目录与属性为结构化数据。旧版基础传输入口继续使用系统 sftp。独立文件标签保留各自的双栏路径和选中项。双栏均读取目录项属性（类型、大小、修改时间），支持文件名筛选、主目录/根目录快捷跳转、拖拽、递归复制、远端重命名和移动、权限修改、空目录删除及小型 UTF-8 文件编辑。文本写入会检查原内容及权限，并通过 OpenSSH 原子重命名扩展发布。

TransferCore 将任务写入 SQLite，最多三项并发。暂停与应用重启后可恢复。续传使用任务 UUID 指定临时文件，恢复前比较字节前缀，发布前再次比较全部内容和文件大小。默认拒绝覆盖现有目标（下载通过同目录硬链接发布，上传通过 SFTP RENAME 发布）；当用户显式开启并二次确认覆盖同名普通文件时，上传通过 OpenSSH `posix-rename@openssh.com` 扩展原子替换，下载通过同目录 `rename` 原子替换。取消保留临时文件便于诊断，传输页提供已完成记录清理及失败/取消任务的 `.part` 临时文件清理确认。递归任务按文件入队，目录结构先创建，失败可能保留已创建目录。暂未实现高延迟网络下的多请求传输流水线。
